Event Bus in Kotlin

Implement a publish-subscribe event bus in Kotlin: subscribe, unsubscribe, publish. A common Android machine coding round question, solved in the browser and checked by tests.

By Vivek Choudhary, Android engineer · Updated October 2026

MediumAbout 35 min7 automatic tests
Open it in the editor

Problem

Implement a publish-subscribe Event Bus that allows components to communicate without direct references to each other.

Functional Requirements
  • subscribe(eventType, listener) — Register a listener for an event type. Returns a unique subscriptionId.
  • unsubscribe(subscriptionId) — Remove a specific subscription
  • publish(eventType, data) — Notify all active listeners for that event type
  • Multiple listeners can subscribe to the same event type
  • Unsubscribing one listener should not affect others

What the tests check

  • subscribe returns unique ids
  • publish notifies every listener of that type
  • listeners of other event types are not called
  • unsubscribe stops only that listener
  • publishing with no listeners does not crash
  • unsubscribing an unknown id does not crash
  • a listener can unsubscribe itself while being notified

Hints

Hint 1

What data structure lets you look up all listeners for a given event type instantly?

Hint 2

Use a Map<String, Map<String, Listener>> — outer key is eventType, inner key is subscriptionId. This gives O(1) subscribe, unsubscribe, and publish.

Hint 3

For subscriptionId, use a UUID or a simple incrementing counter. Store a reverse mapping (subscriptionId → eventType) so unsubscribe doesn't need to scan all event types.

Approach

Data Structure

Use two maps: listeners: Map<EventType, Map<SubId, Listener>> and subscriptionIndex: Map<SubId, EventType>. The second map makes unsubscribe O(1) without scanning.

What most candidates miss
  • ConcurrentModificationException — if a listener modifies subscriptions during publish, iterate a copy
  • Memory leaks — not cleaning up empty event type entries after all listeners unsubscribe
  • Not handling the case where unsubscribe is called with an invalid ID

Reference solution

Try it yourself first. Then compare: the solution passes all 7 tests.

Show the Kotlin solution
class EventBus {
    private val listeners = HashMap<String, LinkedHashMap<String, (Any) -> Unit>>()
    private val typeOf = HashMap<String, String>()   // subscriptionId -> eventType
    private var nextId = 0

    @Synchronized
    fun subscribe(eventType: String, listener: (Any) -> Unit): String {
        val id = "sub-${++nextId}"
        listeners.getOrPut(eventType) { LinkedHashMap() }[id] = listener
        typeOf[id] = eventType
        return id
    }

    @Synchronized
    fun unsubscribe(subscriptionId: String) {
        val type = typeOf.remove(subscriptionId) ?: return   // unknown id: nothing to do
        val forType = listeners[type] ?: return
        forType.remove(subscriptionId)
        if (forType.isEmpty()) listeners.remove(type)         // no empty entries left behind
    }

    fun publish(eventType: String, data: Any) {
        val snapshot = synchronized(this) { listeners[eventType]?.values?.toList() } ?: return
        snapshot.forEach { it(data) }                        // a copy, so listeners may (un)subscribe safely
    }
}
