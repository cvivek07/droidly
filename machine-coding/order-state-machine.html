Order State Machine in Kotlin

Implement a food-order state machine with Kotlin sealed classes. A common Android machine coding round question, solved in the browser and checked by tests.

By Vivek Choudhary, Android engineer · Updated October 2026

Problem

Implement a finite state machine for a food delivery order lifecycle using Kotlin sealed classes.

State Transitions
  • Placed → (Confirm) → Confirmed
  • Confirmed → (StartPreparing) → Preparing
  • Preparing → (Dispatch) → OutForDelivery
  • OutForDelivery → (MarkDelivered) → Delivered
  • Any state except Delivered → (Cancel) → Cancelled
Functional Requirements
  • transition(event) — Apply event, return true if valid, false if invalid for current state
  • getStatusDescription() — Return a human-readable status string
  • Invalid transitions must not change state

What the tests check

  • the happy path: Placed → Confirmed → Preparing → OutForDelivery → Delivered
  • an invalid event returns false and keeps the state
  • steps cannot be skipped
  • Cancel works from every active state
  • Delivered is final: nothing moves it, not even Cancel
  • Cancelled is final
  • status text follows the state

Hints

Hint 1

Use sealed classes for both OrderState and OrderEvent. This gives exhaustive when expressions.

Hint 2

In transition(), use a when(currentState) outer block, then when(event) inner block. Any unmatched combination returns false.

Hint 3

The Cancel event is valid from most states — handle it in each non-terminal state's branch, or use an outer check before the main when block.

Approach

Sealed Class State Machine

Use nested when expressions. Outer: current state. Inner: incoming event. Only valid pairs update currentState and return true. Everything else returns false without mutating state.

What most candidates miss
  • Allowing Cancel from Delivered state — Delivered is terminal, nothing should transition out
  • Not returning false for unrecognised events — a default else clause matters
  • Missing the Cancelled → any transition (Cancelled is also terminal)

Reference solution

Show the Kotlin solution
sealed class OrderState {
    object Placed : OrderState()
    object Confirmed : OrderState()
    object Preparing : OrderState()
    object OutForDelivery : OrderState()
    object Delivered : OrderState()
    object Cancelled : OrderState()
}

sealed class OrderEvent {
    object Confirm : OrderEvent()
    object StartPreparing : OrderEvent()
    object Dispatch : OrderEvent()
    object MarkDelivered : OrderEvent()
    object Cancel : OrderEvent()
}

class OrderStateMachine(initialState: OrderState = OrderState.Placed) {
    var currentState: OrderState = initialState
        private set

    fun transition(event: OrderEvent): Boolean {
        val next: OrderState? = when (val s = currentState) {
            OrderState.Delivered, OrderState.Cancelled -> null                // terminal states
            else -> when (event) {
                OrderEvent.Cancel -> OrderState.Cancelled
                OrderEvent.Confirm -> if (s == OrderState.Placed) OrderState.Confirmed else null
                OrderEvent.StartPreparing -> if (s == OrderState.Confirmed) OrderState.Preparing else null
                OrderEvent.Dispatch -> if (s == OrderState.Preparing) OrderState.OutForDelivery else null
                OrderEvent.MarkDelivered -> if (s == OrderState.OutForDelivery) OrderState.Delivered else null
            }
        }
        if (next == null) return false
        currentState = next
        return true
    }

    fun getStatusDescription(): String = when (currentState) {
        is OrderState.Placed         -> "Order placed, awaiting confirmation"
        is OrderState.Confirmed      -> "Order confirmed by restaurant"
        is OrderState.Preparing      -> "Your food is being prepared 👨‍🍳"
        is OrderState.OutForDelivery -> "Out for delivery 🛵"
        is OrderState.Delivered      -> "Delivered! Enjoy your meal 🍱"
        is OrderState.Cancelled      -> "Order cancelled"
    }
}
