In-Memory Cache with TTL in Kotlin

Build a generic in-memory cache with per-entry TTL in Kotlin. A common Android machine coding round question, solved in the browser and checked by tests.

By Vivek Choudhary, Android engineer · Updated October 2026

Problem

Implement a generic in-memory cache with TTL (time-to-live) expiry for each entry.

Functional Requirements
  • put(key, value, ttlMs) — Store entry with an expiry time (defaults to defaultTtlMs)
  • get(key) — Return value if key exists and not expired, otherwise null
  • evictExpired() — Proactively remove all expired entries
  • size() — Return count of non-expired entries
Expiry Rule

An entry expires when currentTime >= insertionTime + ttlMs. Expired entries should not be returned by get even if not yet evicted.

What the tests check

  • get returns a fresh value
  • get returns null for a missing key
  • an entry expires after its own TTL
  • the default TTL is used when none is given
  • entries with a longer TTL stay alive
  • put on an existing key resets its value and TTL
  • size() counts only entries that have not expired
  • evictExpired() removes expired entries

Hints

Hint 1

Store both the value and its expiry timestamp in a wrapper class.

Hint 2

Use a data class: CacheEntry(value: V, expiryAt: Long). Compute expiryAt = System.currentTimeMillis() + ttlMs at insertion time.

Hint 3

In get(), if entry exists but System.currentTimeMillis() >= entry.expiryAt, treat it as a miss (optionally remove it lazily). In size(), count only entries where expiryAt > currentTime.

Approach

Lazy Expiry + Proactive Eviction

Store Map<K, CacheEntry<V>> where each entry carries its absolute expiry timestamp. Lazy expiry on get — check and return null if expired. evictExpired() does a full sweep.

What most candidates miss
  • Thread safety — concurrent reads/writes need synchronization or ConcurrentHashMap
  • size() returning stale count — must filter expired entries
  • Not removing lazily-expired entries from the map (memory leak)

Reference solution

Try it yourself first. Then compare: the solution passes all 8 tests.

Show the Kotlin solution
class TTLCache<K, V>(private val defaultTtlMs: Long = 5000L) {
    private data class Entry<V>(val value: V, val expiresAt: Long)

    private val map = HashMap<K, Entry<V>>()

    private fun now() = System.currentTimeMillis()

    @Synchronized
    fun put(key: K, value: V, ttlMs: Long = defaultTtlMs) {
        map[key] = Entry(value, now() + ttlMs)
    }

    @Synchronized
    fun get(key: K): V? {
        val e = map[key] ?: return null
        if (now() >= e.expiresAt) { map.remove(key); return null }   // lazy expiry
        return e.value
    }

    @Synchronized
    fun evictExpired() {
        val t = now()
        map.entries.removeIf { t >= it.value.expiresAt }
    }

    @Synchronized
    fun size(): Int {
        val t = now()
        return map.values.count { t < it.expiresAt }
    }
}
