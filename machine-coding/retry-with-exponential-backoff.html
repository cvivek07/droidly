Retry with Exponential Backoff in Kotlin

Retry a suspending call with exponential backoff using Kotlin coroutines. A common Android machine coding round question, solved in the browser and checked by tests.

By Vivek Choudhary, Android engineer · Updated October 2026

Problem

Implement a retry mechanism with exponential backoff that wraps any suspending function and retries it automatically on failure.

Functional Requirements
  • Retry up to maxAttempts times on exception
  • Delay between retries grows exponentially: initialDelay × multiplier^attempt
  • Cap delay at maxDelayMs to avoid unbounded waits
  • If all attempts fail, throw the last exception
  • If an attempt succeeds, return the result immediately
Delay Schedule (example)
  • Attempt 1 fails → wait 100ms
  • Attempt 2 fails → wait 200ms
  • Attempt 3 fails → wait 400ms (or maxDelay, whichever is lower)

What the tests check

  • returns at once when the first attempt succeeds
  • retries until it succeeds
  • throws the last exception after maxAttempts
  • waits initialDelay, then initialDelay × multiplier (about 150 ms total)
  • caps each delay at maxDelayMs

Hints

Hint 1

Use a loop from 1 to maxAttempts. Wrap each attempt in try-catch.

Hint 2

Track the current delay. After each failure (except the last), call delay(currentDelay) then multiply currentDelay by the multiplier. Use minOf(currentDelay, maxDelayMs) to cap it.

Hint 3

The function signature should be generic: suspend fun retryWithBackoff(..., block: suspend () -> T): T. Rethrow on last attempt by checking attempt == maxAttempts.

Approach

Loop + Coroutine Delay

Loop through attempts. On success return early. On failure, if it's the last attempt rethrow. Otherwise compute delay = min(initialDelay × multiplier^(attempt-1), maxDelay), suspend with delay(), then continue.

What most candidates miss
  • Retrying on ALL exceptions — in production you'd filter: retry only on transient errors, not 4xx client errors
  • Not using minOf to cap the delay
  • Jitter — adding a small random offset to delays prevents thundering herd in distributed systems

Reference solution

Try it yourself first. Then compare: the solution passes all 5 tests.

Show the Kotlin solution
suspend fun <T> retryWithBackoff(
    maxAttempts: Int = 3,
    initialDelayMs: Long = 100L,
    multiplier: Double = 2.0,
    maxDelayMs: Long = 5000L,
    block: suspend () -> T
): T {
    require(maxAttempts >= 1) { "maxAttempts must be at least 1" }
    var nextDelay = initialDelayMs.toDouble()
    repeat(maxAttempts - 1) {
        try {
            return block()
        } catch (e: CancellationException) {
            throw e                       // never swallow cancellation
        } catch (e: Exception) {
            delay(minOf(nextDelay.toLong(), maxDelayMs))
            nextDelay *= multiplier
        }
    }
    return block()                        // last attempt: let its exception propagate
}
