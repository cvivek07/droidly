Token Bucket Rate Limiter in Kotlin

Build a per-user token bucket rate limiter in Kotlin with lazy refill. A common Android machine coding round question, solved in the browser and checked by tests.

By Vivek Choudhary, Android engineer · Updated October 2026

Problem

Implement a Token Bucket Rate Limiter that controls how many requests each user can make per second.

Functional Requirements
  • isAllowed(userId) — Return true if the request is permitted, false if rate limited
  • Each user gets their own independent bucket
  • Bucket refills at a fixed rate over time (not just at fixed intervals)
  • Bucket has a max capacity — tokens don't accumulate beyond it
Token Bucket Rules
  • Each request consumes 1 token
  • Tokens refill continuously at refillRatePerSecond
  • If bucket is empty → request is denied
  • Users start with a full bucket

What the tests check

  • a new user starts with a full bucket (3 requests pass)
  • the request after the burst is denied
  • each user has an independent bucket
  • tokens refill over time
  • refill never goes above maxTokens
  • fractional refill works (no integer rounding)

Hints

Hint 1

You don't need an actual background thread to refill tokens. How can you calculate how many tokens should have been added since the last request, using only the current timestamp?

Hint 2

Store the last-access timestamp per user. On each request, compute elapsed time → multiply by refill rate → add tokens (capped at maxTokens).

Hint 3

Use a data class to hold each user's current token count and last refill timestamp. Use System.currentTimeMillis() for time tracking.

Approach

Lazy Refill Strategy

Don't use a background thread. Instead, calculate tokens lazily: on each request, check how much time has elapsed since the last request for that user, compute how many tokens should have been added, and top up the bucket.

Per-user State

data class Bucket(
  var tokens: Double,
  var lastRefillTime: Long
)
What most candidates miss
  • Using integer tokens instead of Double — causes precision loss with fractional refill rates
  • Not capping tokens at maxTokens after refill
  • Thread safety — a real implementation needs synchronization per user bucket

Reference solution

Try it yourself first. Then compare: the solution passes all 6 tests.

Show the Kotlin solution
class TokenBucketRateLimiter(
    private val maxTokens: Int,
    private val refillRatePerSecond: Double
) {
    private class Bucket(var tokens: Double, var lastRefillNanos: Long)

    private val buckets = HashMap<String, Bucket>()

    @Synchronized
    fun isAllowed(userId: String): Boolean {
        val now = System.nanoTime()
        val bucket = buckets.getOrPut(userId) { Bucket(maxTokens.toDouble(), now) }
        val elapsedSeconds = (now - bucket.lastRefillNanos) / 1_000_000_000.0
        bucket.tokens = minOf(maxTokens.toDouble(), bucket.tokens + elapsedSeconds * refillRatePerSecond)
        bucket.lastRefillNanos = now
        if (bucket.tokens >= 1.0) {
            bucket.tokens -= 1.0
            return true
        }
        return false
    }
}
