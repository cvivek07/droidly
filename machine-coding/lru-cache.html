LRU Cache in Kotlin

Implement an LRU cache in Kotlin with O(1) get and put. A common Android machine coding round question, solved in the browser and checked by tests.

By Vivek Choudhary, Android engineer · Updated October 2026

MediumAbout 45 min8 automatic tests
Open it in the editor

Problem

Design and implement a Least Recently Used (LRU) Cache. It should support get and put operations in O(1) time.

Functional Requirements
  • get(key) — Return the value if the key exists, otherwise return -1. Accessing a key marks it as recently used.
  • put(key, value) — Insert or update the key-value pair. If the cache is at capacity, evict the least recently used entry before inserting.
Non-Functional Requirements
  • Both operations must run in O(1) time
  • Capacity is fixed at construction time

Example

val cache = LRUCache(2)
cache.put(1, 1)
cache.put(2, 2)
cache.get(1)    // → 1  (1 is now most recent)
cache.put(3, 3) // evicts key 2
cache.get(2)    // → -1 (evicted)
cache.get(3)    // → 3

What the tests check

  • get returns -1 for a missing key
  • put then get returns the value
  • evicts the least recently used key when full
  • get marks a key as recently used
  • put on an existing key updates it without evicting
  • updating a key also makes it most recent
  • capacity 1 keeps only the latest key
  • handles 100,000 operations quickly (O(1))

Hints

Hint 1

What data structure gives you O(1) lookup by key?

Hint 2

To track recency, you need to know both the most recent and least recent entries quickly. A doubly linked list lets you remove and add nodes in O(1) — combine it with a HashMap.

Hint 3

Use a HashMap<Int, Node> where each Node is in a doubly linked list. On every get/put, move that node to the head (most recent). The tail is always the LRU candidate to evict.

Approach

Data Structure

Use a HashMap + Doubly Linked List. The map gives O(1) access to any node. The linked list maintains recency order — head is most recent, tail is least recent.

Key Operations

  • get: Look up node in map → move to head → return value
  • put: If key exists, update + move to head. If new, add at head. If over capacity, remove tail node and its map entry.
What most candidates miss
  • Using LinkedHashMap shortcut — fine for production but expect a "implement from scratch" follow-up
  • Forgetting to update the map when evicting the tail node
  • Off-by-one: checking capacity before insertion vs after

Reference solution

Show the Kotlin solution
class LRUCache(private val capacity: Int) {
    private class Node(val key: Int, var value: Int) {
        var prev: Node? = null
        var next: Node? = null
    }

    private val map = HashMap<Int, Node>()
    private val head = Node(0, 0)   // sentinel: most recent side
    private val tail = Node(0, 0)   // sentinel: least recent side

    init { head.next = tail; tail.prev = head }

    fun get(key: Int): Int {
        val node = map[key] ?: return -1
        moveToFront(node)
        return node.value
    }

    fun put(key: Int, value: Int) {
        val existing = map[key]
        if (existing != null) {
            existing.value = value
            moveToFront(existing)
            return
        }
        if (map.size == capacity) {
            val lru = tail.prev!!
            unlink(lru)
            map.remove(lru.key)
        }
        val node = Node(key, value)
        map[key] = node
        addFront(node)
    }

    private fun unlink(n: Node) { n.prev!!.next = n.next; n.next!!.prev = n.prev }
    private fun addFront(n: Node) { n.next = head.next; n.prev = head; head.next!!.prev = n; head.next = n }
    private fun moveToFront(n: Node) { unlink(n); addFront(n) }
}
